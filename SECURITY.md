# Security policy

## Supported versions

Only the latest release receives fixes.

## What is in scope

This is a local learning stack. It is not hardened for production, and some of its defaults are
deliberately simple:

- the Airflow UI uses `SimpleAuthManager` with every user as admin, so it asks for no login;
- the warehouse and the object storage use the example credentials of `.env.example`;
- the ports are published the Docker way, on every network interface of the machine.

Run it on a trusted network only, and do not expose it to the internet as it is. [docs/architecture.md](docs/architecture.md#what-would-change-in-production)
lists what would change in production.

Secrets (`AIRFLOW_FERNET_KEY`, `AIRFLOW_JWT_SECRET`) are generated by `make env` into `.env`,
which is git-ignored. A secret committed to the repository, or a way for a DAG to leak one into
the logs, is a bug worth reporting.

## Reporting a vulnerability

Please do not open a public issue. Use GitHub's private vulnerability reporting ("Security" tab,
"Report a vulnerability") or contact the maintainer directly. You should get an answer within a
week.
